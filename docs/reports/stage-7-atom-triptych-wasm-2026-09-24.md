# Stage 7 Atom Triptych WASM adapter proof

**Date:** 2026-09-24
**Status:** passed as an opt-in bare-host predicate
**Atom revision:** `468461b`
**Triptych revision:** `44ba31043fbce95df82bb4e07ea607c8c03c688d`

This is the first replacement-host proof for the Atom runner. The Atom
package now exports `createTriptychWasmExecutionAdapter()`. It accepts the
Triptych `TriptychCpu` constructor from the host, so Atom does not import Rust,
Triptych or a browser runtime. The adapter implements the existing Atom
execution seam only: mutable 64 KiB memory, the selected registers and flags,
single-instruction stepping, and a bounded halt result.

The predicate assembles the same source through the existing Debug80 Runtime
reference adapter and the Triptych WASM adapter:

```text
ORG 4000H
START: LD A,42
       DB 42
```

It compares the materialised image, IMAGE and PATCH records, host-service
trace and success status. The exact observed result was:

| Field | Triptych WASM | Debug80 reference |
| --- | ---: | ---: |
| materialised bytes | `3` | `3` |
| materialised SHA-256 | `caa1cc95c081d5a6a0b5302289cb5e1e2e8e44ac26fdb587fd4a230a6db7f067` | same |
| instructions | `11,478` | `11,354` |
| cycles | `115,411` | `115,411` |
| host-service calls | `5` | `5` |
| result | pass | pass |

The instruction counts differ because the two engines expose repeated Z80
block instructions at different stepping granularity. The generated bytes,
service order and cycle total are the qualified observables for this proof;
the execution profile must not silently treat instruction count as a portable
value until that stepping convention is versioned.

The adapter deliberately keeps the runner's memory in JavaScript-owned storage
and synchronises it at instruction boundaries. A persistent wasm-bindgen view
can be detached when the module grows linear memory for a later host
allocation. This is slower than a production bulk path but makes the
conformance result deterministic. A native Triptych adapter remains a separate
gate; the existing `ATOM.COM` native/WASM CP/M distribution proof covers the
production machine path while that bare-host adapter is developed.

## Reproduction

From a checkout containing both repositories:

```sh
cd /Users/johnhardy/projects/triptych
npm run build:wasm-host
cd /Users/johnhardy/projects/atom
TRIPTYCH_WASM_MODULE=/Users/johnhardy/projects/triptych/dist/wasm/triptych_host_wasm.js \
  npm run verify:triptych-wasm
```

This proof is intentionally opt-in because Atom's normal release checks must
remain runnable without a Triptych checkout. The reference adapter remains a
differential oracle; this change does not add a Debug80 dependency to Triptych
production code.
